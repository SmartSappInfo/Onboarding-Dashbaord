# 1. PRODUCT DEFINITION

## 1.1 Product vision

SmartSapp Media Intelligence is the unified content infrastructure for the SmartSapp platform.

It enables organizations to:

**Manage → Understand → Publish → Distribute → Track → Personalize → Automate → Attribute → Optimize**

digital content across:

* CRM
* Leads
* Contacts
* Deals
* Pipelines
* Campaigns
* Messaging
* Meetings
* Knowledge
* Landing Pages
* Automations
* AI
* Sales workflows

The product must evolve beyond a "media library" into a platform service that understands both the **content itself** and the **business behavior generated by that content**.

---

# 2. PROBLEM STATEMENT

The current Media implementation already converts uploaded or linked media into tracked experiences and captures playback, milestones, CTA activity, automation actions, and CRM identity.

However, the current model is primarily organized around:

```text
Asset
→ Share
→ Viewer
→ Events
→ CTA
→ Automation
→ Analytics
```

The 2.0 architecture must support:

```text
Asset
→ Version
→ Processing
→ AI Understanding
→ Collection
→ Experience
→ Distribution
→ Identity
→ Session
→ Event Graph
→ CRM Context
→ Attribution
→ Automation
→ AI Recommendation
→ Business Outcome
```

# 3. PRODUCT OBJECTIVES

## Primary objectives

1. Establish a canonical media platform layer for the entire SmartSapp application.
2. Support scalable multi-format asset management.
3. Separate asset identity from presentation, versioning, delivery, and tracking.
4. Create a canonical Media Event Graph.
5. Make media engagement a first-class CRM signal.
6. Connect media activity to contacts, leads, companies, deals, campaigns, meetings, and revenue.
7. Provide deep content intelligence using AI.
8. Provide natural-language media search and analysis.
9. Provide a customizable Media Experience Builder.
10. Provide enterprise-grade permissions, lifecycle management, governance, security, and auditability.
11. Support high-scale analytics without turning Firestore into the primary analytical warehouse.
12. Make media usable everywhere in SmartSapp through reusable APIs and components.

---

# 4. NON-GOALS

Media Intelligence 2.0 is not initially intended to become:

* a general-purpose social network
* a full professional video editing suite
* a replacement for enterprise DAM platforms in every use case
* a video conferencing platform
* a full LMS
* a general web CMS

The architecture must nevertheless support future expansion toward those adjacent capabilities.

# 5. PRODUCT PRINCIPLES

## 5.1 Asset is not experience

A media asset is the underlying content.

An experience is how that content is presented.

A link is how an experience is distributed.

A session is how someone interacts with it.

An event is what happened.

An attribution record explains its business impact.

This separation is foundational.

# 21. Firestore document sizing rules

The implementation must avoid:

* unlimited event arrays
* unlimited transcript arrays inside asset documents
* large session timelines embedded in single documents
* huge analytics counters updated by every client directly

Large content and event structures must be partitioned.

Use:

* subcollections
* aggregates
* time buckets
* append-only event streams
* denormalized read models

# 24. EVENT INGESTION CONTRACT

All events must support:

```json
{
  "schemaVersion": 1,
  "eventType": "VIDEO_PROGRESS",
  "occurredAt": "serverTimestamp",
  "workspaceId": "ws_123",
  "assetId": "asset_123",
  "versionId": "ver_4",
  "experienceId": "exp_123",
  "sessionId": "session_123",
  "visitorId": "visitor_123",
  "contactId": "contact_123",
  "payload": {
    "progress": 0.74,
    "positionMs": 182000
  }
}
```

### Event principles

* client must never define authoritative timestamps when server receipt time is required
* every event is schema-versioned
* events are idempotent
* duplicate events must not double-count business metrics
* event IDs must be globally unique within workspace context
* sensitive fields must obey workspace privacy policies

Example:

```text

THEN
Apply Tag "High Media Intent"
```

Media owns the signal.

The central automation engine owns the action orchestration.

# 36. MEDIA INTENT SCORE

Separate engagement from intent.

A person can watch a training video for 20 minutes without being a purchase lead.

Intent signals include:

* pricing content
* proposal
* product comparison
* booking CTA
* repeated sessions
* multiple high-value assets
* form completion
* deal-stage context

# 37. ATTRIBUTION MODEL

The platform must distinguish:

## Touched

Contact interacted with media.

## Engaged

Meaningful interaction occurred.

## Assisted

Media appeared in the journey and plausibly contributed.

## Influenced

Media had a measurable relationship with a downstream CRM outcome.

## Converted-after-exposure

Conversion happened after meaningful media engagement.

Never represent all of these as "media caused the sale."
